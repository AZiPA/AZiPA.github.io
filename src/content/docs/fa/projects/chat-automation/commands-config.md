تمام دستورات مدیریتی در **چت خصوصی** با ربات اجرا می‌شوند و رفتار زمان اجرا از طریق ثابت‌های فایل `tgcloud/lib/config.js` همراه با تنظیمات ذخیره‌شده در SQLite کنترل می‌گردد.

## دستورات مالک (Owner Commands)

:::note[دسترسی انحصاری Fail-Closed در چت خصوصی]
دستورات فقط در چت خصوصی و برای `owner_id` ثبت‌شده پاسخ می‌دهند. پیام‌های سایر کاربران و گروه‌ها به صورت خودکار نادیده گرفته می‌شوند.
:::

| دستور | عملکرد |
| :--- | :--- |
| `/start` | دوره خنک‌سازی ۱۰ دقیقه‌ای تاپیک‌ها (`topics_disabled_until`) را پاک کرده و داشبورد **🤖 Telegram Business Assistant Status** را نمایش می‌دهد. |
| `/start bizChat<chatId>` | لینک عمیق `/start` برای نمایش **Contact Archive Summary** (خلاصه بایگانی مخاطب) در آن چت بیزینس. |
| `/trigger` | متن تریگر فعلی یک‌بارمشاهده (پیش‌فرض `.`)، وضعیت `/autodelete` و راهنمای استفاده را نمایش می‌دهد. |
| `/trigger <text>` | یک متن تریگر تک‌خطی دلخواه (`۱ تا ۳۲` کاراکتر، بدون حساسیت به حروف کوچک و بزرگ) تنظیم می‌کند. |
| `/trigger reset` | متن تریگر یک‌بارمشاهده را به مقدار پیش‌فرض `.` بازمی‌گرداند. |
| `/autodelete` | وضعیت فعلی حذف خودکار (پیش‌فرض فعال) را نشان می‌دهد و در صورت نبود دسترسی `can_delete_all_messages` هشدار می‌دهد. |
| `/autodelete on` | حذف خودکار ریپلای‌های دقیق تریگر یک‌بارمشاهده را با `deleteBusinessMessages` فعال می‌کند. |
| `/autodelete off` | حذف خودکار را غیرفعال می‌کند تا ریپلای‌های تریگر در چت بیزینس باقی بمانند. |

## پیکربندی زمان اجرا (`tgcloud/lib/config.js`)

| ثابت (Constant) | مقدار پیش‌فرض | عملکرد |
| :--- | :--- | :--- |
| `RETENTION_DAYS` | `30` | تعداد روز نگهداری رکوردهای `messages` پیش از پاک‌سازی فرصت‌طلبانه. |
| `RAW_UPDATES_RETENTION_DAYS` | `3` | تعداد روز نگهداری لاگ‌های `raw_updates` پیش از حذف دوره‌ای. |
| `DEFAULT_VIEW_ONCE_TRIGGER` | `'.'` | متن پیش‌فرض ریپلای دقیق (بدون حساسیت به حروف کوچک و بزرگ) برای حذف خودکار. |
| `MAX_TRIGGER_LENGTH` | `32` | حداکثر طول مجاز کاراکتری در دستور `/trigger <text>`. |
| `DELETE_TRIGGER_REPLY` | `true` | وضعیت پیش‌فرض حذف خودکار ریپلای‌های دقیق تریگر. |
| `CAPTURE_UNARCHIVED_REPLIES` | `true` | ذخیره رسانه یک‌بارمشاهده روی ریپلای، حتی اگر پیام اصلی قبلاً بایگانی نشده باشد. |
| `NOTIFY_UNARCHIVED_DELETES` | `true` | ارسال اعلان خلاصه برای پیام‌های حذف‌شده قبل از اتصال ربات یا پیام‌های بایگانی‌نشده. |
| `MAX_DELETE_BATCH` | `25` | حداکثر تعداد پیام ورودی بایگانی‌شده در هر آپدیت حذف (همراه با اعلان سرریز در صورت تجاوز). |
| `MAX_GETFILE_BYTES` | `20971520` (`20 MB`) | سقف حجم دانلود از Bot API برای ارسال جایگزین با `InputFile`. |
| `DEBUG_RAW_UPDATES` | `false` | پرچم اختیاری برای ذخیره آپدیت‌های خام تلگرام در جدول `raw_updates` جهت عیب‌یابی. |

## نکات کاربردی استفاده

### عملکرد تریگر هوشمند ترکیبی

ذخیره رسانه‌های یک‌بارمشاهده برای پیام‌های `photo`، `video`، `voice` و `video_note` زمانی عمل می‌کند که **پیش از باز کردن** رسانه روی آن ریپلای بزنید—حتی اگر تلگرام ابتدا یک `view_once_placeholder` بدون `file_id` فرستاده باشد:

- **ریپلای طبیعی (هر متنی):** رسانه یک‌بارمشاهده را در چت خصوصی ربات (یا تاپیک اختصاصی مخاطب) ذخیره و ارسال می‌کند و پیام ریپلای شما در چت بیزینس باقی می‌ماند.
- **ریپلای دقیق با تریگر (پیش‌فرض `.`، بدون حساسیت به بزرگی و کوچکی حروف):** رسانه را ذخیره کرده **و** در صورت روشن بودن `/autodelete` و وجود دسترسی `can_delete_all_messages`، پیام ریپلای شما را بلافاصله با `deleteBusinessMessages` پاک می‌کند.
- **ایمنی تلاش مجدد:** اگر ارسال مستقیم با `file_id` شکست بخورد، ربات فایل را تا سقف `20 MB` (`MAX_GETFILE_BYTES`) دانلود و با `InputFile` مجدداً آپلود می‌کند؛ اگر باز هم خطا رخ دهد، ثبت قفل دیتابیس بازگردانی می‌شود تا با ریپلای دوباره بتوانید تلاش کنید.

### نگهداری داده و لاگ تشخیصی

- پاک‌سازی فرصت‌طلبانه به طور خودکار روی حدود ۲٪ از آپدیت‌های `business_message` اجرا می‌شود و رکوردهای `messages` قدیمی‌تر از `30` روز (`RETENTION_DAYS`) و `raw_updates` قدیمی‌تر از `3` روز (`RAW_UPDATES_RETENTION_DAYS`) را حذف می‌کند.
- در استفاده عادی، `DEBUG_RAW_UPDATES` را روی `false` نگه دارید تا داده‌های خام JSON ذخیره نشوند.
